## 〇、三块基石（必须先理解）

这三条是整个 SEO 文案体系的地基。不理解它们，后面的一切技巧都是空中楼阁。

### 基石 ①：TDK 已死，现在是 TDH

传统 SEO 说页面三要素是 Title、Description、Keywords——但 **Keywords 标签早在十年前就被谷歌淘汰**。站长疯狂往 Keywords 里塞大词蹭排名，谷歌不再信任它。

**现在真正决定排名的三要素是 TDH：**

| 要素                    | 给谁看的        | 作用                                                     | 重要级别   |
| ----------------------- | --------------- | -------------------------------------------------------- | ---------- |
| **Title（标题）**       | 搜索引擎 + 用户 | 判断页面主题的第一信号；搜索结果里的蓝字，决定用户点不点 | ⭐⭐⭐⭐⭐ |
| **Description（描述）** | 用户为主        | 不直接参与排名，但影响点击率；搜索结果里的灰色摘要文字   | ⭐⭐⭐     |
| **H1（一级标题）**      | 搜索引擎 + 用户 | 页面主题的第二信号；一个页面有且仅有一个                 | ⭐⭐⭐⭐   |

**H2–H6 同样重要**——它们是页面的骨架，搜索引擎通过 Headings 层级来理解页面覆盖了哪些子话题。你的关键词密度控制、content outline、内链锚文本，全都依赖 Headings 结构来实现。

> 📖 哥飞公众号《从 TDK 到 TDH》（2024-04-06），《哥飞实战手册》：谷歌爬虫爬取网页时会获取 Headings、正文和图片 alt，然后根据这些来判断页面主题。

---

### 基石 ②：六字真言——分门别类罗列

哥飞社群反复验证的核心打法，六个字：**分门别类罗列**。

本质是用 Headings 结构把关键词组清晰摊开在页面上，让搜索引擎一眼看清你的页面覆盖了什么。这既是内容原则，也是结构原则，更是权重汇聚原则。

以哥飞拆解的 startup.jobs 为例——该站过去 12 月总访问量 1136 万，靠的就是首页 Headings 结构把"按岗位类型分类""按城市分类""按技能分类"全部分门别类列出来，每个分类下面又有子分类，搜索引擎能清晰理解站点的覆盖范围。哥飞的评价是"**最佳首页结构**"。

以 Ahrefs 的 writing-tools 页面为例：

```
writing tools（一级页面，排名第 3）
  ├── paraphrase tool → /writing-tools/paraphrasing-tool
  ├── grammar checker → /writing-tools/grammar-checker
  ├── outline generator → /writing-tools/outline-generator（二级页面，排名第 1）
  ├── paragraph generator → /writing-tools/paragraph-generator
  └── conclusion generator → /writing-tools/conclusion-generator
```

Ahrefs 做的：在一级页面（writing-tools）里把所有三级工具列出来并链接，同时对有搜索量的二级关键词（如 outline-generator）单独建工具页。

Ahrefs 没有做的：为那些很少有人搜的二级关键词单独建页面——**做页面，只做用户可能会搜索的关键词。**

> 📖 哥飞《两大 SEO 原则：分门别类罗列和一个关键词一个页面》（2025-01-15）；案例拆解 startup.jobs（2025-11-10）

---

### 基石 ③：一个关键词一个页面，举全站之力

**一个页面聚焦一个核心关键词 + 它的语义变体组。**

很多人误解为"一个网站对一个词只能做一个页面"——哥飞引用了 Ahrefs 的 Patrick Stox，明确指出这个理解是**错误的**。一个核心关键词可以有很多变种说法和二级、三级细分词，每一个细分关键词都可以做一个页面。

**正确的理解是：**

- 一个核心关键词 → 一个页面（首页）
- 它的变体说法（同语义）→ 在同一页面自然覆盖
- 它的二级、三级细分关键词 → 各自独立页面（内页）
- 所有页面通过内链形成**树状结构**，权重从末梢逐层向主干汇聚

这就是**「举全站之力做一个关键词」的真实含义**——不是只做一个首页完事，而是一个首页 + 一批二级三级内页 + 合理内链，把整站权重汇聚到核心关键词。

哥飞在群聊里说得非常直白：_"千万不要简单理解为注册一个域名，做一个首页就完事。"_

具象化就是树状结构：通过合理的内链结构，可以把权重从主干传递到支干，也能到枝叶，还可以把所有枝叶和支干的权重汇聚到核心关键词主页。

> 📖 哥飞《关于关键词蚕食，关于页面结构，关于如何举全站之力优化关键词》（2025-01-14）

## 一、首页文案规范

### 1.1 首页定位

**首页的使命：用域名 + 首页吃主词，用内页吃二级/三级词。**

首页天然权重最高——这里有四个原因：

1. **外链权重汇聚到首页**：别人传播时默认传播首页，外链权重都落在首页
2. **内链权重汇聚到首页**：全站所有页面都有指向首页的内链，内页获取的外部权重最终传导汇聚到首页
3. **用户行为数据集中在首页**：大多数网站用户访问频率最高的页面
4. **核心关键词设在首页**：品牌词和核心关键词通常都在首页

因为首页权重最高，所以你应该**在首页给重要内页添加入口**——这又导致更多用户从首页进入内页，进一步提升内页的用户行为数据，形成正向循环。

如果你的首页能去打竞品的内页，**结构上有天然优势**。因此选对主词后，首页的 Title、H1、Headings 结构、正文、内链全部围绕它展开。

> 📖 哥飞《为什么有些关键词流量巨大但 Ahrefs 查询出来的 KD 很低》（2024-11-11）

---

### 1.2 Logo 的 HTML 规范

首页 Logo 用 H1 标签，内页 Logo 用 div 标签——因为内页的 H1 另有用途。

```html
<!-- 首页 Logo -->
<h1 class="logo">
  <a href="./">Brand Name</a>
</h1>

<!-- 内页 Logo -->
<div class="logo">
  <a href="./">Brand Name</a>
</div>
```

CSS 要去掉 H1 的默认样式：

```css
.logo {
  font-size: 22px;
  font-weight: bold;
  font-style: normal; /* 去掉 h1 默认斜体 */
  background-color: black;
  color: white;
  padding: 0 8px;
  border-radius: 6px;
}
```

> 📖 哥飞《养网站防老第 4 步：手动调整布局和样式》（2024-08-12）

---

### 1.3 Title 写法

**核心原则：主词打头，自然串联变体，品牌名放最后。**

```
✅ Face Shape Analyzer – Free AI Face Shape Detection & Report | Brand
❌ Free AI Face Analyzer & Full Face Report | Brand（主词被稀释，自造词占位）
```

拆解逻辑：

- 最前面放置完整核心关键词（搜索引擎判断你页面关于什么的第一个信号）
- 中间用自然语言串联 1-2 个同语义变体（语义化串联，不是堆砌）
- 末尾放品牌名
- 总长度控制在 **50–60 字符**（Google 桌面端截断线约 60 字符）

另一个来自 aiphoto.com 教程中的示例：

```
✅ AI Text to Image Generator | Create Images from Text Free Online | AIPhoto
```

哥飞对 aidocmaker.com 的点评原文：_"可以在一个页面的标题里合理组合多个关键词，注意不是简单的堆砌，而是要有一定的语义化，组成一句比较自然的句子，尽可能把不同的说法都覆盖到。"_

参考：豆瓣电影页面的 Title 非常简单就是"电影名称（豆瓣）"——但那是**因为豆瓣已有足够权重**。新站没有资格玩花活，必须在 Title 里精准命中用户会搜的关键词。

> 📖 哥飞《5800 字长文：从网站站内优化到部署上线再到推广运营》（2024-08-13）

---

### 1.4 Description 写法

**不影响排名，但决定点击率。** 必须包含核心关键词，同时让用户知道点进来能得到什么。

结构：一句话告诉用户「这能干什么」+ 一句话给行动理由。控制在 **150–160 字符**。

```
✅ Upload one photo to detect your face shape, symmetry, and proportions with AI. Get a full report with style recommendations in seconds.
❌ The best face shape analyzer on the internet. Try it now!（空洞无价值主张）
```

Description 的实用价值：**用户搜了你的主词、看到 Title 决定搜不搜你、看到 Description 决定点不点你。** 你的内容也许排名不前，但如果 Description 写得好，点击率照样可能高于排在你前面的结果。

> 📖 哥飞《5800 字长文》（2024-08-13）；社群成员袁锐钦 SEO 全流程帖子（2026-04-05）

---

### 1.5 H1 写法

**H1 直接写核心关键词。一个页面有且仅有一个 H1。**

```
✅ Face Shape Analyzer
❌ Discover Your True Face Shape with AI（好看但不完整命中关键词）
```

例外：如果核心关键词太短（1–2 词），可加功能性后缀使其更自然，但要确保完整关键词在前。比如 `QR Code Generator` 写 `QR Code Generator – Create Custom QR Codes Free`。

为什么不能像豆瓣那样写得很简单？因为豆瓣已经有绝对权重。新站没有资格玩花活——搜索引擎需要 TDH 三者一致才能精准理解你的页面主题。

---

### 1.6 Headings 骨架（分门别类罗列）

首页用 H1 → H2 → H3 结构把主词下的子话题全部列出。**H2 的文本必须包含二级关键词。**

**模板：**

```
H1: [核心关键词]

  H2: How [核心关键词] Works
    H3: Step 1 — [动作描述]
    H3: Step 2 — [动作描述]
    H3: Step 3 — [动作描述]

  H2: [子分类/功能 A]
    [简短描述 + 内链指向对应内页]

  H2: [子分类/功能 B]
    [简短描述 + 内链指向对应内页]

  H2: [子分类/功能 C]
    [简短描述 + 内链指向对应内页]

  H2: Why Use [核心关键词]
    [3–5 个卖点，每个一个 H3 或独立段落]

  H2: Frequently Asked Questions
    [4–6 个 FAQ，用 FAQPage 结构化数据标记]
```

以 Coloring Pages 站为例（哥飞在群聊里的示例）：

```
H1: Coloring Pages

  H2: Dog Coloring Pages
    H3: Cute Dog Coloring Pages → 图片 × N
    H3: Little Dog Coloring Pages → 图片 × N
    H3: Realistic Dog Coloring Pages → 图片 × N

  H2: Cat Coloring Pages
    H3: Cute Cat Coloring Pages → 图片 × N
    H3: Kitten Coloring Pages → 图片 × N

  H2: Flower Coloring Pages
    H3: Red Flower Coloring Pages → 图片 × N
    H3: Sunflower Coloring Pages → 图片 × N
```

不是内容站的专利——工具站也一样用。Ahrefs 的 writing-tools 页面用同样的结构拿到了 `writing tools` 的谷歌第 3 名。

**关键规则：**

- H1 只能有一个
- H2 的数量没有硬性上限，4–8 个比较合理
- 每个 H2 下面至少有 1 个 H3
- **所有含关键词的 H2/H3 处放置内链，指向对应子页面**——内链锚文本就是关键词本身

参考 startup.jobs — 哥飞评价其 Headings 结构为"最佳首页结构"，靠的是把岗位、城市、技能全部分门别类罗列，每个分类下面又有子分类，搜索引擎能清晰理解站点的覆盖范围。

### 1.7 正文规范

| 指标         | 标准                                                              |
| ------------ | ----------------------------------------------------------------- |
| 总字数       | **800–2000 词**（少于 600 严重不合格）                            |
| 关键词密度   | **3%–5%**（不是死线，但落在这范围里大概率不会出错）               |
| 正文地址原则 | **使用子目录，不要子域名**（`site.com/page` 而非 `sub.site.com`） |

子目录 vs 子域名的选择：哥飞在群聊中明确建议用 `/docs` 方式而非 `doc.domain.com` 方式。因为子域名上获得的外链权重向主域名传递会有损耗，而子目录方式下所有外链都指向同一域名，权重通过内链汇聚到首页更顺畅。

密度太低 = 写了太多不相关的东西；密度太高 = 堆砌。**让 AITDK 插件查出来的 2 词 / 3 词密度排行榜里，主词排在前 3 名即可。**

密度控制的最佳方法是 **用 Headings 搭骨架**——每个 H2/H3 区域自然包含关键词，这样密度就不需要刻意数。

哥飞在群聊里的原话：_"控制关键词密度，其实是为了让你写内容时不偏题。3%–5% 不是一个一定要达到的标准，而是说如果你落在这个范围内，大概率不会出错。如果太小，说明你写了太多不相关的东西，如果太多，说明内容不够，全靠关键词堆砌。"_（2025-12-11）

### 1.8 img 规范

每个 `<img>` 必须写 `alt` 属性。alt 是对图片的文字描述，专门写给搜索引擎看的。包含页面关键词。图片尽量 300×300 以上。

```html
<!-- 正确的图片标签 -->
<img
  src="face-shape-oval.png"
  alt="Oval face shape analysis result"
  width="400"
  height="300"
/>

<!-- 文件名要有意义 -->
✅ qr-code-generator.png ❌ image1.png
```

**额外规则：**

- 使用 WebP 格式（比 PNG 小 50% 以上）
- 设置宽高属性，避免布局偏移（影响 Core Web Vitals）
- 图片延迟加载（loading="lazy"）

> 📖 社群成员袁锐钦 SEO 全流程帖子（2026-04-05）

### 1.9 导航条（全站统一）

导航条是**权重汇聚的核心机制**。全站所有页面都用相同的导航条组件，导航条里包含首页链接，这样所有页面的权重都自动汇聚到首页。

```html
<nav>
  <div class="nav-links">
    <a class="curr" href="./">Home</a>
    <a href="face-shape-oval/">Oval Face Shape</a>
    <a href="face-shape-round/">Round Face Shape</a>
    <a href="face-shape-square/">Square Face Shape</a>
    <a href="face-attractiveness-analyzer/">Attractiveness Test</a>
    <a href="blog/">Blog</a>
  </div>
</nav>
```

当前页面加 `curr` 类（用不同颜色或加粗标识），方便用户知道自己在哪里。

导航条链接更容易被谷歌选中放到 Sitelinks 里——而 Sitelinks 能让你的网站在搜索结果里占据更大面积，提高点击率。

> 📖 哥飞《养网站防老第 4 步》（2024-08-12）；群聊记录：Sitelinks 机制讨论（2024-09-24）

### 1.10 Footer

## 二、工具页 / 功能页文案规范

### 2.1 工具页布局铁律：先给答案，再给工具

用户搜一个工具词时的心态是「我现在就要用」。**不要让他们先读三段话再找入口。** 布局顺序是：

```
1. H1（立刻告诉用户这是他要的工具）             ← 首屏可见
2. 工具入口（表单/上传区/按钮，无需滚动）       ← 首屏可见
3. 简短一句话说明（10–15 词）                   ← 首屏可见
4. 正文开始（How it works / Features / FAQ）    ← 以下可滚动
```

哥飞拆解 Ahrefs 的 outline-generator 页面原文：_"页面打开之后，就是我们提过无数次的，经典工具页面布局，先大大的 H1 标题放核心关键词，然后下面就是工具表单入口，之后是大段大段的介绍性文字。"_

**反例**：不要先来三段"AI is changing the world..."再给工具入口。用户会直接关掉回到搜索结果，这对你的用户行为数据（停留时间、跳出率、返回搜索率）是毁灭性的。

> 📖 哥飞《两大 SEO 原则》（2025-01-15）

### 2.2 Logo 归属：H1 留给工具

工具页的 H1 是工具标题本身，Logo 改用 div：

```html
<div class="logo">

</div>

<h1>Tool Core Keyword</h1>

<!-- 工具入口 -->
<div class="tool-container">...</div>
```

这与首页的两个关键区别：

1. Logo 不是 H1（H1 给了工具标题）
2. 导航条里的首页链接放第一个位置，确保权重向首页汇聚

> 📖 哥飞《养网站防老第 4 步》（2024-08-12）

### 2.4 工具页为什么需要大段文字

很多新手不理解：我做的是工具，为什么要在工具下面写几百字的文字？用户是来用工具的，不是来阅读的。

哥飞的解释：**因为谷歌爬虫不可能像人一样操作你的工具。它只能通过"看"你网页里的文字来理解这个工具是什么，能解决什么问题。**

谷歌的处理流程：

1. 爬虫抓取你的 HTML，读到 TDH + Headings + 正文
2. 谷歌选择**先相信你说的话**
3. 给你一些曝光，观察用户行为——他们会不会点进来？点进来停留多久？有没有立刻返回搜索结果？
4. 通过积累用户行为数据，判断你是否说了真话
5. 如果满足用户需求 → 给更多流量；如果持续满足 → 排名上升，最终可能拿下第一名

所以工具页的大段文字不是写给用户看的而是写给搜索引擎看的——**用户行为数据才是写给用户看的**。文字帮谷歌理解你，工具帮用户喜欢你，两者缺一不可。

> 📖 哥飞《两大 SEO 原则》（2025-01-15）

### 2.5 FAQ 结构化数据

工具页和功能页的 FAQ 区域使用 **FAQPage 结构化数据**（JSON-LD 格式）。谷歌会在搜索结果里直接展示可折叠的问答，让你在搜索结果里占据更大面积，提高点击率。

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "How accurate is the face shape analyzer?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Our AI face shape analyzer achieves over 95% accuracy..."
      }
    },
    {
      "@type": "Question",
      "name": "Do I need to create an account to use this tool?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "No sign-up required. Upload your photo and get results instantly for free."
      }
    }
  ]
}
```

**FAQ 建议覆盖的问题类型：**

- 工具精度/准确性问题
- 使用门槛（是否需要注册、是否免费）
- 隐私安全（上传的文件如何处理）
- 支持的格式/文件大小限制
- 与竞品的差异比较
- 使用场景举例

## 三、通用规则（首页和工具页都适用）

### 3.1 关键词组策略

一个页面不是只做一个词，而是做一个**关键词组**——核心关键词 + 2~5 个同语义变体。

**同语义判断标准：搜索意图一致。** 比如 `face shape analyzer` 和 `face shape detection`、`face shape test` 是同组（用户都想上传照片测脸型）。但 `face shape analyzer` 和 `face attractiveness test` 是不同组（一个要分类、一个要打分），应该分到两个页面。

覆盖方式：

- Title 放 1~2 个最主要的变体
- H2/H3 放其他变体
- 正文自然穿插同义说法
- Description 带 2~3 个变体

哥飞在拆解 notta.ai 时强调：一个页面围绕着一个核心关键词去做，实际上是能够承接住这个核心关键词的变种词的流量的。**"我们说的一个关键词一个页面，指的是一个核心关键词一个页面。"**

> 📖 案例拆解 notta.ai（2025-11-05）

---

### 3.2 不要用自造词

用户不会搜你发明出来的、没有搜索量的词。如果在 Title、H1 的关键位置放了自造词，谷歌不认识它，它占着位子反而稀释了真实关键词的权重。

**判断方法**：去谷歌趋势或谷歌 Ads 关键字规划师查这个词有没有搜索量。没有量 + KD 报告里没有任何站在做这个词 = 自造词。

如果你确实需要给产品起个特色名字，放在正文里当品牌概念讲，别放进 Title 和 H1 的黄金位置。

---

### 3.3 关键词密度控制

**3%–5% 是经验范围**，不是数学公式。如果正文 800 词，3% 就是出现约 24 次核心关键词。不需要精确到小数点——**用 AITDK 插件查出的 2 词密度排行榜里，主词排在前 3 名即可**。

控制密度的最佳工具不是计数器，而是 **Headings 骨架**。一个词在 H1、H2、正文开头、内链锚文本中各出现一遍，密度自然达标。

密度太低 → 可能写了太多不相关的东西，谷歌认为你偏题。
密度太高 → 内容不够全靠堆砌，有被判定为 spam 的风险。

正确做法：关键词出现在自然的位置（标题、第一段、H2/H3 标签、最后一段），不刻意堆砌。

> 📖 群聊记录：关键词密度讨论（2025-12-11）；社群成员袁锐钦 SEO 全流程帖子（2026-04-05）

---

### 3.4 后端渲染 / SSR 是底线

以上所有内容——TDH、Headings、正文、alt、结构化数据——**必须直接出现在服务端返回的 HTML 源码里**，不能靠前端 JS 动态渲染。

判断方法：浏览器右键 → 查看网页源代码，搜索你的 H1 文本，能找到就是对的。找不到说明是 CSR（客户端渲染），谷歌可能抓不到你的内容。

在哥飞社群里，SSR vs CSR 是高频讨论话题。群友李小猿总结得最清楚：

- **SSR（服务端渲染）**：服务器直接生成完整 HTML 文档，包含所有页面内容。搜索引擎爬虫无需执行 JavaScript 即可获取完整内容。天然支持所有搜索引擎爬虫的解析。
- **CSR（客户端渲染）**：初始 HTML 为空容器，需要浏览器执行 JS 后才加载内容。谷歌虽然宣称能渲染 JS，但实际的抓取预算、渲染时效、重试机制都不如 SSR 可靠。

**新站老老实实 SSR，别赌谷歌会不会执行 JS。** 如果用 Next.js，确保页面使用 `getServerSideProps` 或者在 App Router 中默认 SSR。用 Vite 建的 CSR 项目，需要改配置适配 SSR。

> 📖 群聊记录：SSR vs CSR 讨论（2025-03-12、2025-08-21）

---

### 3.5 URL 唯一性

每个页面通过 `<link rel="canonical">` 指定唯一规范化 URL。同时确保：

- `www` 和裸域名只留一个（另一个 301 跳转）
- `http` → `https` 301 跳转
- 同一页面不能有多个 URL 都能访问（否则谷歌会看到多个 URL 返回相同内容，影响收录）

```html
<link rel="canonical" href="https://mysite.com/tools/face-shape-analyzer/" />
```

> 📖 哥飞《从需求调研到网站规划》（2024-11-25）

### 3.6 关键词域名是天然优势

如果你的域名里包含核心关键词的一部分，这就是优势信号。`myfacereport.com` 里包含 "face"——全文围绕 face shape 展开，域名 + TDH + 正文三者形成最强语义闭环。

哥飞在群聊里讲过 title-generator.com 和 titlegenerator.com 的对比：带连字符的前者月访问 87K，不带连字符的后者只有 14K——因为前者是精确匹配域名，直接拿下了 `title generator` 和 `headline generator` 等词的排名。

**社群里还有个经典案例**：Qiang Gao 的域名是 ab.com，他优化的关键词是 "a b"（有空格），但谷歌反而让 "ab"（无空格）排名第 2——因为 "ab" 就是他的域名，域名关键词匹配直接帮他把无空格词拿下了排名。

> 📖 群聊记录：headline generator 讨论（2024-10-24）；Qiang Gao 案例（2026-02-22）

---

### 3.7 内容长度 ≠ 目标，满足用户意图才是

800–2000 词是经验线，但不是越长越好。哥飞对 aidocmaker 案例的点评抓住了核心：**"能够满足用户需求，才是重中之重。人均访问 3 个页面，跳出率 37%，停留时间 2 分钟，都能够说明网站能够满足用户需求，能够留住用户。"**

不要为了凑字数而写废话。如果用户要的是工具，给他工具；如果用户要的是答案，在首屏给他答案。**搜索引擎不看你写了多少字，看的是用户是否不需要再回搜索结果页。** 这个信号比你写 5000 字管用。

另一个案例：anythingtranslate.com 一年内从 0 冲到月访问量 77 万，DR 只有 31 个网站给外链。哥飞总结它成功的核心是：找的词搜索量不大但逐渐增长、竞争低的词，工具页直接满足用户需求 → 用户行为数据好看 → 排名持续上升。

> 📖 aidocmaker 案例总结（2026-01-24）；案例拆解 anythingtranslate.com（2025-10-29）

## 四、内链策略

### 4.1 树状结构

**内链的本质是权重传递——从末梢向主干层层汇聚。**

```
首页 ← 二级页面 ← 三级页面
  ↑        ↑          ↑
  └── 所有页面都有链接指向首页
       └── 每个页面都有链接指向上一级
```

具体做法：

1. **全站统一的导航条/页脚**包含首页链接 → 所有页面向首页汇聚权重
2. **首页的 H2/H3 区域**用关键词锚文本链接到对应二级页面 → 权重向二级传递
3. **二级页面正文/底部**用关键词锚文本链接回首页 → 权重回传
4. **三级页面**链接到对应的二级页面 + 首页

哥飞原话：_"通过合理的内链结构，可以把权重从主干传递到支干，也能到枝叶。还可以把所有枝叶和支干的权重汇聚到核心关键词主页。"_

> 📖 哥飞《关于关键词蚕食，关于页面结构，关于如何举全站之力优化关键词》（2025-01-14）；群聊记录（2024-05-09）

---

### 4.2 导航条汇聚权重

全站所有页面用相同的导航条组件，导航条里必然包含首页链接。**这是权重汇聚最基础的机制**——所有页面的权重都通过导航条自动向首页汇聚。

哥飞原话解释：首页权重高的第四个原因是"整个网站的全部页面，都会给首页内链，这就导致内页获取的外部权重也会最终传导汇聚到首页"。

> 📖 哥飞《为什么有些关键词流量巨大但 KD 很低》（2024-11-11）

---

### 4.3 锚文本规范

锚文本是内链的可点击文字。**用关键词做锚文本，而不是用"点击这里"。**

```
✅ <a href="/qr-code-generator/">QR Code Generator</a>
✅ <a href="/face-shape-analyzer/">Face Shape Analyzer</a>
❌ <a href="/tool1">click here</a>
❌ <a href="/page2">learn more</a>
```

**锚文本要有多样性**——不要 100 个内链的锚文本都是完全相同的精确匹配关键词。可以混合使用核心词、变体说法、品牌名、URL 裸链等不同形式。

这一原则同样适用于外链建设。社群里 HJ 的总结：同一个域名的多个外链价值是快速递减的 —— 第 1 个链接价值 100%，第 2-5 个大幅下降，第 N 个趋近于零。

> 📖 群聊记录：外链锚文本讨论（2025-10-29）；HJ 外链经验分享（2026-02-04）

---

### 4.4 博客→工具页 单向引流

工具站最有效的 SEO 策略：**写围绕工具的博客文章，用博客的长尾关键词流量引导用户到工具页。**

```
博客文章 → 工具页（单向引流）
"how to create a QR code for wifi" → /qr-code-generator/
"what is a QR code" → /qr-code-generator/
"QR code vs barcode" → /qr-code-generator/
```

每篇博客文章底部加 CTA：`Try our free QR Code Generator →` 链接到工具页。这样做一举两得：既给工具页增加了内链权重，又把博客的长尾流量转化成了工具页用户。

这就是社群成员赫兹说的 "低 KD 多内页" 打法——不是靠一个大词打天下，而是靠大量低竞争的长尾博客文章聚沙成塔，所有文章的内链最终汇聚到你的核心工具页面。

> 📖 社群成员袁锐钦 SEO 全流程帖子（2026-04-05）

---

### 4.5 Sitelinks 辅助

Sitelinks 是谷歌在搜索结果里自动展示的"子链接"——品牌词搜索结果里，网址下方出现的那一排快速导航链接（如 Pricing、Blog、Contact 等）。

虽然 Sitelinks 不能直接控制，但有一些方法可以增加被选中的概率：

1. **全站统一的导航条**——导航条里的链接更容易被谷歌选中放入 Sitelinks
2. **某些页面有很多内链或外链**——如定价页面被很多文章内链指向
3. **用户在谷歌搜索里频繁直接搜索某个子页面**——如很多用户搜 "xxx pricing"，谷歌就会把 Pricing 放入 Sitelinks

获得 Sitelinks 意味着：你的品牌词搜索结果几乎霸屏——48% 的搜索用户会点击 Sitelinks 中的一个链接。

> 📖 群聊记录：Sitelinks 机制讨论（2024-09-24）

## 五、结构化数据（Schema Markup）

结构化数据是一种告诉谷歌"这个页面是什么类型的内容"的标记方式。添加后你的搜索结果可能显示额外的信息（星级评分、FAQ 折叠、价格、面包屑等），占据更大面积，提高点击率。

所有结构化数据使用 **JSON-LD 格式**，放在页面 `<head>` 中。

### 5.1 WebApplication

适用于工具页面，告诉谷歌这是一个在线工具。

```json
{
  "@context": "https://schema.org",
  "@type": "SoftwareApplication",
```

## 六、页面类型决策树

当 Agent 接到用户需求，如何决定建什么类型的页面？按以下流程判断。

```
用户搜索词意图分析
│
├─ 信息型（how to、what is、why）
│  └─ 写博客文章 / 教程
│     例子："how to create a QR code for wifi"
│     做法：标准博客页，TDH + 教程步骤 + 图片 + 最后 CTA 引流到工具页
│
├─ 商业调研型（best、top、vs、review）
│  └─ 写对比评测 / 榜单文章
│     例子："best qr code generator 2026"
│     做法：列表综述页，每个产品一个 H2 + 简短评测 + 外链和 CTA
│
├─ 交易型（buy、price、discount、free、online）
│  └─ 建工具页 / 产品页
│     例子："free qr code generator"
│     做法：标准工具页，工具入口首屏 + H2-H3 结构 + FAQ 结构化数据
│
├─ 导航型（品牌名、产品名）
│  └─ 确保品牌词排名第一
│     做法：首页 Title = "Brand Name - 一句话描述"；如果竞品抢占品牌词排名，需要额外优化
│
└─ 无明确意图 / 歧义词
   └─ 查看 SERP 里排前面的页面类型，跟着主流意图走
      例：搜 "qr code" 排在前面的是工具页 → 这个词是工具意图 → 建工具页
```

## 八、域名选购指南

域名是网站的第一资产。结合哥飞社群的经验：

**1. 首选关键词精确匹配域名（EMD）**

如 title-generator.com 比 titlegenerator.com 流量大得多（87K vs 14K）。关键词域名 + 举全站之力优化，拿下排名的成功率大幅提升。

**2. 连字符域名的取舍**

title-generator.com 拿到好排名验证了连字符不是问题。但要注意：不要用多个连字符（如 free-online-title-generator.com），一个连字符是极限，两个以上看着像 spam。

**3. 注册前用域名历史工具查前世**

很多看似可用的域名其实是二手域名，可能有黑历史——被谷歌惩罚过、做过 PBN、挂过垃圾外链。使用 Wayback Machine 或哥飞网站的[域名前世档案工具](https://seo.web.cafe/history/)查询。

**4. .com 优先，其次 .ai**

如果做 AI 工具，.ai 域名也是不错的选择。其他后缀（如 .xyz、.online）尽量避开，用户信任度低。

**5. 域名年龄有一定作用，但不是决定性因素**

哥飞的社群案例：title-generator.com（2015 年注册）流量远大于 titlegenerator.com（2005 年注册）。域名年龄有帮助，但精准匹配+内容质量才是决定性因素。

## 九、Agent 自检清单

写完一个页面后，逐条核对：

| #   | 检查项         | 通过标准                                             | 不通过时的后果                                                 |
| --- | -------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| 1   | Title          | 核心关键词在最前面，总长 ≤ 60 字符                   | 搜索引擎可能无法准确识别页面主题                               |
| 2   | H1             | 有且仅有一个，完整包含核心关键词                     | 多个 H1 会让谷歌困惑，无法判断页面核心主题                     |
| 3   | Description    | 150–160 字符，含关键词 + 行动理由                    | 不影响排名但影响点击率；空缺时谷歌会自行截取你可能不想要的段落 |
| 4   | Headings 层级  | H1 → H2 → H3 树状，不倒挂（如没有 H2 就直接跳到 H3） | 搜索引擎难以理解内容结构，关键词密度无法自然达标               |
| 5   | 关键词密度     | 3%–5%，2 词密度榜排前 3                              | 太低 → 偏题，太高 → 可能被判定为堆砌                           |
| 6   | 正文长度       | ≥ 800 词                                             | 少于 600 词严重不合格，谷歌可能认为你的内容不足以回答用户问题  |
| 7   | img alt        | 所有 `<img>` 有 alt 属性，含页面关键词               | 谷歌无法理解图片内容，错失图片搜索流量                         |
| 8   | 内链           | 每页有 2–5 个内链指向其他页面                        | 孤岛页面——权重无法传递，用户无法跳转                           |
| 9   | canonical      | 已设置唯一规范化 URL                                 | 同一页面多个 URL 被收录，权重分散                              |
| 10  | SSR            | 查看源代码能搜到 H1 文本                             | CSR 页面可能不被谷歌抓取或延迟抓取                             |
| 11  | 自造词         | Title/H1 里没有自造的、无搜索量的词                  | 自造词占位稀释真实关键词权重                                   |
| 12  | FAQ 结构化数据 | 有 FAQ 区域的页面已加 FAQPage schema                 | 错失搜索结果里的富媒体展示机会                                 |
| 13  | 工具入口位置   | 工具页的工具入口在首屏，H1 正下方                    | 用户看不到入口 → 立刻返回搜索结果 → 用户行为数据变差           |
| 14  | 导航条         | 全站统一，包含首页链接                               | 没有统一的导航条意味着权重无法汇聚到首页                       |
| 15  | Footer         | 包含版权信息 + Privacy/Terms 链接                    | AdSense 过审受阻；缺乏信任要素                                 |
| 16  | HTTPS          | 全站启用 HTTPS                                       | Google 明确表示 HTTPS 是排名信号，没有 HTTPS 排名受影响        |
| 17  | 移动端适配     | 手机上显示正常，按钮可点击，文字可读                 | Google 实行移动优先索引，移动端体验差直接影响排名              |
| 18  | 页面速度       | LCP < 2.5s, CLS < 0.1                                | 速度慢导致用户在加载完成前离开，搜索引擎会据此降低排名         |

## 十、常见错误与避坑

以下是哥飞社群三年多来，新手最常踩的坑：

### 10.1 上线后什么都不做，干等流量

网站不是扔上去等就有流量的。**第一天就必须提交 Google Search Console、提交 Sitemap、手动请求索引首页。** 不敲门，谷歌不会自己找上门。新站上线后通常需要几天到几周谷歌才会主动发现你，但主动提交可以把等待期压缩到数小时到数天。

### 10.2 用自造词当主词

在 Title 和 H1 里放了没有搜索量的自造词——比如你的产品功能是生成人脸报告，你称它为"Full Face Report"，但这个词用户在谷歌里一次都没搜过。搜索引擎不认识这个词，用户不搜这个词，你排上去了也没人点。

**解决方案**：用谷歌 Ads 关键字规划师或谷歌趋势验证任何一个你想放进 Title/H1 的词是否有搜索量。没有量就别放。

### 10.3 关键词堆砌

不是把十个关键词塞进 Title 就能拿到十个词的排名——反而可能被判定为 spam，降权。关键词要自然出现在 Title、H2、正文第一段和最后一段，而不是机械罗列。

### 10.4 忽略移动端

谷歌已经实行**移动优先索引**——它主要看你的网站在手机上的表现来决定排名。如果你的网站在手机上显示混乱、文字太小、按钮点不到，排名一定上不去。每个页面上线前，用手机打开看一遍。

### 10.5 不做内链

很多新手的网站是"孤岛"——每个页面独立存在，互相没有链接。这等于告诉谷歌"这些页面之间没有关系"，而且用户也无法浏览更多内容（跳出率飙升）。每个页面至少有 2–5 个内链。

### 10.6 频繁改版

频繁修改页面 URL、标题、内容结构，会让谷歌的索引混乱，每次大改都可能丢失已有的排名。小修小改可以（改文案、加内容），大改要慎重（改 URL、删页面）。如果必须改 URL，一定要做好 **301 重定向**。

### 10.7 买垃圾外链

2026 年，谷歌识别和惩罚购买外链的能力非常强。被查到，轻则排名下降，重则整站被 K。**不要走这条路。** 新站优先做"安全外链"：目录提交、导航站收录、Hacker News 提交、在 Reddit 相关板块自然分享。PBN（Private Blog Network）式的外链虽然诱惑但得不偿失——哥飞专门写了教程解释 PBN 为何不值得碰。

### 10.8 把首页和内容页搞混

首页不要塞满长篇大论的介绍——用户来首页是想看到你能干什么、有什么工具，不是来读你的公司简介。长篇正文留给内页；首页用 Headings 骨架分门别类罗列子功能。

### 10.9 无关词密度超标

正文里反复出现的是你自己关心的词（比如公司产品名称、行业术语），而不是用户会搜的词（比如核心关键词和变体）。这会导致谷歌认为你的页面和用户搜索的关键词不相关，从而不给排名。

**判断方法**：用 AITDK 插件查看 2 词密度排行榜。如果前三名里没有你的核心关键词和变体，说明你写偏了。

## 十一、SEO 时间线（给用户设预期）

如果你在帮用户建站，需要帮他设好心理预期。以下是新站的典型 SEO 时间线：

### 第 1–2 周：收录期

- 手动请求索引后，Google 会在几天内收录首页
- 检查方法：GSC → 索引 → 页面 → 搜索你的域名
- 如果没收录：检查 robots.txt、检查 SSR（服务端渲染）、检查是否有 noindex 标签

### 第 4–6 周：初步排名期

- 收录后，Google 开始评估页面质量
- 你可能在第 50–100 名，翻好几页才能找到——**这是正常的**
- 不要因为看不到排名就改来改去
- 继续发布内容、优化现有页面、获取外链

### 第 2–3 个月：稳定排名期

- 如果你的内容质量过关，排名会逐渐上升
- 长尾关键词可能先有排名（竞争小）
- 主关键词可能还在 10–20 名
- 开始有少量自然搜索流量（每天十几个到几十个访客）

### 第 6 个月：长尾流量起量期

- 大量长尾词页面开始贡献流量
- 如果做了几十个内页，每个页面每天几个到几十个访问，累计起来就很可观
- 社群成员赫兹的 41K 月访问量就是靠大量低 KD 内页聚沙成塔

### 一个真实案例（社群成员赫兹）

- **2025.08**：开始上线网站
- **2025.09-10**：20 多个站大部分没声响，焦虑期
- **2025.10**：一个站开始有起色
- **2025.11**：专注优化，月收入 $990
- **2026.02**：月收入突破 $4,000

从上线到月入千刀，花了 4 个月。其中前 3 个月几乎没有收入。

**SEO 是复利游戏**——前期积累慢，一旦突破临界点，流量和收入加速增长。
