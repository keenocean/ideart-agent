# Reconstructed Condensing Rules

This file is a reconstructed functional reference inferred from `SKILL.md`. It is not an original creative platform side file.

## Goal

When a script exceeds the session duration cap and the user chooses condensed production, preserve the strongest ad logic while reducing runtime. Do not rewrite for creativity; trim for fidelity.

## Beat Priority

Keep in this order:

1. Hook/opening scene.
2. Product reveal or named solution.
3. CTA/end card.
4. One proof, demo, or transformation beat.
5. One problem/agitation beat only if it is necessary for the reveal to make sense.

Drop first:

- Repeated problem examples.
- Long testimonials after the proof point is clear.
- Extra feature bullets.
- Secondary offers.
- Scene transitions that carry no new meaning.

## Duration Recipes

| Target | Recommended scene count | Scene budget                                                 |
| -----: | ----------------------: | ------------------------------------------------------------ |
| 12-15s |                     2-3 | hook 4-5s, reveal/demo 5-6s, CTA 3-4s                        |
| 20-24s |                     3-4 | hook 5s, problem/proof 5-6s, reveal 7-8s, CTA 4-5s           |
|    30s |                     3-5 | hook 6s, problem 5s, solution/demo 9-10s, proof 4-5s, CTA 5s |

## VO Trimming

- Keep the first sentence of the hook unless it is over 3.0 words/second.
- Keep product name exactly.
- Keep legal or required disclaimer text exactly.
- Trim filler: "really", "just", "kind of", "you know", repeated setup clauses.
- Prefer shorter sentences over faster voice speed.
- Recalculate words per second for each condensed scene; target 2.0-2.8 w/s, max 3.0 w/s.

## Merge Rules

- Merge problem + product reveal only when product name naturally resolves the problem.
- Merge proof + CTA only if proof is a short phrase on the end card.
- Never merge two speakers into one persona unless the original script had only one speaker.
- Never invent a new bridge line; use existing VO or remove the transition.

## Condensed Output Record

When condensing, write a short decision note before production:

```text
Condensed plan: original {ORIGINAL_SECONDS}s -> {TARGET_SECONDS}s cap.
Kept scenes: {HOOK}, {PRODUCT_REVEAL}, {CTA}, {OPTIONAL_PROOF}.
Dropped/merged scenes: {LIST}.
VO changes: trimmed for timing only; product name, legal copy, and CTA preserved.
```

This note prevents downstream directors from treating the shortened cut as a newly invented script.
