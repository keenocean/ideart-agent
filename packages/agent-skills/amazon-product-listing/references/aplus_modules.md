# Reconstructed A+ Module Rules

This file is a reconstructed functional reference inferred from `SKILL.md` and common Amazon A+ content structure. It is not an original creative platform side file.

## Seven-Module Narrative

1. Hero banner: brand promise plus product beauty shot.
2. Pain points: category frustration or buyer problem the product solves.
3. Feature matrix: 3-5 core features with icons or short descriptions.
4. Ingredients/materials/technology: what it is made of or powered by.
5. Efficacy/proof/benefit mechanism: verified reason to believe, without unsupported claims.
6. How to use: 3-step usage flow or routine integration.
7. Brand endorsement/sign-off: brand values, trust, and family/category close.

## Design Rules

- Modules 1 and 7 use `21:9`; modules 2-6 use `3:2`.
- Use `model="gpt-image-2"` for all A+ modules because text and layout fidelity matter.
- Every module references `main:final` for product consistency.
- Build one visual system across all modules: same palette, typography, icon style, and product lighting.
- Keep mobile cropping in mind: put essential copy and product inside the central 80% width.
- Use concise copy. A+ modules should read as designed tiles, not brochures.

## Claim Discipline

- Use placeholders for unknown proof: `{CERTIFICATION}`, `{LAB_RESULT}`, `{MATERIAL}`, `{OFFER}`.
- Never invent quantified performance, clinical proof, sustainability credentials, safety certifications, awards, or endorsements.
- If the category is regulated, prefer descriptive features over outcome claims.
